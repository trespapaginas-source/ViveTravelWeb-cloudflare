## Plan: Sistema de reseñas real (Cloudflare D1 + Turnstile)

### Arquitectura
- **Backend:** Cloudflare Pages Functions (`functions/api/reviews/`) + **D1** (SQLite serverless). Todo dentro de Cloudflare, gratis.
- **Anti-spam:** Cloudflare **Turnstile** (widget invisible, valida token server-side).
- **Alcance:** Planes + Cabañas.
- **Sin login:** el usuario envía nombre + destino + estrellas (1-5). Sin comentarios.

### Esquema de datos (D1)
```sql
CREATE TABLE IF NOT EXISTS reviews (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  service_type TEXT NOT NULL,      -- 'plan' | 'cabin'
  service_id TEXT NOT NULL,        -- id del plan/cabaña
  reviewer_name TEXT NOT NULL,     -- nombre que escribe el usuario
  destination TEXT NOT NULL,       -- destino que escribe el usuario
  rating INTEGER NOT NULL,         -- 1 a 5
  created_at TEXT NOT NULL DEFAULT (datetime('now')),
  ip_hash TEXT                     -- hash de IP para rate-limit suave
);
CREATE INDEX idx_reviews_service ON reviews(service_type, service_id);
```

### Pasos que requieren TU acción (no puedo hacerlos yo)
Estos requieren tu cuenta de Cloudflare autenticada:

1. **Crear la base de datos D1:**
   ```bash
   npx wrangler d1 create vive-travel-reviews
   ```
   → Copiar el `database_id` que devuelve.

2. **Crear el widget de Turnstile:**
   - Ir a https://dash.cloudflare.com → Turnstile → Add widget
   - Hostname: `vive-travel-web.pages.dev` (+ `localhost` para dev)
   - Modo: **Managed** (invisible para humanos)
   - Guardar el **sitekey** (público, va en el frontend) y el **secret key** (privado).

3. **Configurar el secret de Turnstile:**
   ```bash
   npx wrangler pages secret put TURNSTILE_SECRET
   ```
   → Pegar el secret key.

4. **Aplicar la migración a producción:**
   ```bash
   npx wrangler d1 execute vive-travel-reviews --remote --file=migrations/0001_reviews.sql
   ```

Yo te dejaré marcados con placeholders (`YOUR_DATABASE_ID`, `YOUR_TURNSTILE_SITEKEY`) los valores que debas pegar tras ejecutar esos comandos.

### Flujo de datos
```
Usuario llena form → Turnstile valida (invisible) → 
POST /api/reviews (Function valida token + campos) → 
INSERT en D1 → 
Frontend refetch → muestra reseña + recalcula avg/count
```

### Lo que NO se hace
- **No se eliminan** los `rating`/`reviewCount` de los JSON (se conservan como fallback para el build estático inicial / SSR-like). En runtime, el detalle prioriza los datos reales de D1.
- **No se añade login.** Turnstile + rate-limit por IP hash es la protección.
- **No Transporte/Visas** (confirmaste solo Planes + Cabañas).
- **No comentarios** en las reseñas (solo nombre + destino + estrellas, como pediste).
